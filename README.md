# reality-sni-check

ابزاری برای غربال کردن دامنه‌ها و پیدا کردن گزینه‌های مناسب برای `dest` و `serverNames` در پروتکل REALITY.

به جای حدس زدن یا کپی کردن دامنه از آموزش‌های اینترنتی، یک لیست دامنه به اسکریپت می‌دهید و مشخص می‌کند کدام‌ها از نظر فنی برای REALITY مناسب‌اند و کدام‌ها نیستند.

---

## چرا این ابزار لازم است

در REALITY سرور شما هنگام دریافت ClientHello خودش به `dest` وصل می‌شود و ServerHello واقعی آن سایت را می‌گیرد. یعنی انتخاب `dest` یک تصمیم دلبخواهی نیست و اگر دامنه‌ای شرایط لازم را نداشته باشد، اتصال اصلاً برقرار نمی‌شود.

رایج‌ترین دلایل کار نکردن REALITY:

- دامنه TLS 1.3 پشتیبانی نمی‌کند
- دامنه ALPN با `h2` مذاکره نمی‌کند
- گواهی دامنه معتبر نیست یا اصلاً شامل همان دامنه نمی‌شود
- دامنه پشت CDN مشترک است و رفتارش قابل تشخیص است
- دامنه در کشور شما فیلتر شده است

این اسکریپت همه‌ی این‌ها را به‌صورت خودکار بررسی می‌کند.

## نصب

روی اوبونتو ۲۴٫۰۴ (و هر توزیع مبتنی بر دبیان):

```bash
apt update && apt install -y openssl dnsutils curl jq
git clone https://github.com/rgoogoonani/Reality-sni-check.git
cd reality-sni-check
chmod +x reality-sni-check.sh
```

`jq` اختیاری است ولی اگر نصب نباشد اسکریپت اجرا نمی‌شود؛ همان اول به شما می‌گوید چه چیزی کم دارید.

## استفاده سریع

```bash
# بررسی چند دامنه به صورت مستقیم
./reality-sni-check.sh www.hetzner.com swdist.apple.com dl.google.com

# بررسی یک فایل لیست، با تعیین کشور سرور
./reality-sni-check.sh -f sni-candidates-big.txt -c DE -j 10 -o good.txt
```

## گزینه‌ها

| گزینه | توضیح |
|---|---|
| `-f FILE` | فایل لیست دامنه‌ها؛ هر خط یک دامنه، خطوط با `#` نادیده گرفته می‌شوند |
| `-c CC` | کد کشور سرور شما، مثلاً `DE` — برای سنجش هم‌خوانی جغرافیایی |
| `-j N` | تعداد بررسی موازی (پیش‌فرض ۶) |
| `-t SEC` | تایم‌اوت هر بررسی (پیش‌فرض ۸ ثانیه) |
| `-o FILE` | نوشتن دامنه‌های قابل استفاده (PASS و WARN) در این فایل |
| `-v` | نمایش دلیل کامل هشدارها |
| `-h` | راهنما |

اگر لیست بلندی دارید و به محدودیت نرخ `ipinfo.io` خوردید، می‌توانید توکن بدهید:

```bash
export IPINFO_TOKEN="your_token_here"
./reality-sni-check.sh -f list.txt -c DE
```

## معیارهای بررسی

### رد قطعی — FAIL

اگر هر کدام از این‌ها برقرار نباشد، دامنه برای REALITY قابل استفاده نیست:

- رکورد DNS نوع A دارد
- پورت ۴۴۳ باز و در دسترس است
- TLS 1.3 پشتیبانی می‌شود
- ALPN با `h2` مذاکره می‌شود
- گواهی معتبر است
- گواهی واقعاً شامل همین دامنه است (بررسی SAN با پشتیبانی از wildcard)

### هشدار — WARN

دامنه کار می‌کند ولی ایده‌آل نیست:

- **CDN مشترک** — روی Cloudflare، Akamai، Fastly، CloudFront و مشابه است. هزاران سایت پشت آی‌پی یکسان قرار دارند و الگوی TLS آن‌ها شناخته‌شده‌تر است
- **کشور متفاوت** — کشور آی‌پی با کشوری که با `-c` دادید فرق دارد
- **ریدایرکت** — دامنه به دامنه‌ی دیگری ریدایرکت می‌شود
- **تاخیر بالا** — بیش از ۴۰۰ میلی‌ثانیه؛ چون سرور REALITY در هر هندشیک به `dest` وصل می‌شود، تاخیر بالا مستقیماً روی تجربه کاربر اثر می‌گذارد
- **کلید موقت غیر X25519** — REALITY به تبادل کلید X25519 وابسته است

### قبول — PASS

هیچ خطا و هیچ هشداری ندارد.

## خواندن خروجی

```
DOMAIN                        STATUS IP               CC    ORG
--------------------------------------------------------------------------
www.hetzner.com               PASS   213.133.116.44   DE    AS24940 Hetzner Online GmbH
xp.apple.com                  PASS   17.253.57.210    US*   AS6185 APPLE-AUSTIN, US
cdn.jsdelivr.net              WARN   151.101.65.229   US*   AS54113 FASTLY - Fastly, Inc.
  \_ shared CDN: AS54113 FASTLY - Fastly, Inc.
www.strato.de                 FAIL   192.67.198.33    DE    AS6724 STRATO AG
  \_ ALPN h2 not negotiated

PASS: 2   WARN: 1   FAIL: 1
CC marked with * came from the registry allocation (Team Cymru), not geolocation.
```

**درباره علامت `*` کنار کد کشور:** اسکریپت اول از `ipinfo.io` استفاده می‌کند که موقعیت جغرافیایی واقعی را می‌دهد. اگر در دسترس نبود (مثلاً به دلیل تحریم)، به‌صورت خودکار به **Team Cymru** روی DNS سوییچ می‌کند که محدودیت نرخ ندارد و از هیچ کشوری مسدود نیست.

تفاوتشان: Cymru کشور **ثبت تخصیص** آی‌پی را می‌دهد نه موقعیت فیزیکی. مثلاً یک سرور اپل در فرانکفورت با Cymru `US` گزارش می‌شود چون بلوک آی‌پی به اپل آمریکا ثبت شده. برای همین وقتی `*` می‌بینید، هشدار «country differs» را جدی نگیرید.

تشخیص CDN مشترک در هر دو حالت دقیق است، چون ASN و نام سازمان از هر دو منبع درست می‌آید.

## روند دو مرحله‌ای پیشنهادی

این اسکریپت **سلامت فنی** را می‌سنجد، نه فیلتر بودن را. برای اینکه هر دو را بدانید، دو بار اجرا کنید:

**مرحله ۱ — روی سرور خارج:** غربال فنی

```bash
./reality-sni-check.sh -f sni-candidates-big.txt -c DE -j 10 -o ok-abroad.txt
```

خروجی: دامنه‌هایی که TLS 1.3 و h2 و گواهی سالم دارند، به‌همراه اطلاعات دقیق مالک آی‌پی.

**مرحله ۲ — روی یک ماشین داخل کشور خودتان:** غربال فیلترینگ

```bash
./reality-sni-check.sh -f ok-abroad.txt -c DE -j 10 -v -o final.txt
```

دامنه‌های فیلترشده اینجا FAIL می‌گیرند (تایم‌اوت TCP یا شکست هندشیک).

هرچه در `final.txt` بماند هم فنی سالم است هم در دسترس.

## نکته مهم: تحریم با فیلترینگ فرق دارد

خیلی از این دامنه‌ها (اپل، استیم، انویدیا، ادوبی) خودشان آی‌پی بعضی کشورها را به دلیل تحریم بلاک می‌کنند. این با فیلترینگ فرق دارد و **برای REALITY اهمیتی ندارد**.

چیزی که اهمیت دارد این است که **هندشیک TLS کامل شود**، نه اینکه سایت محتوا بدهد. چون کلاینت REALITY هرگز واقعاً به آن سایت وصل نمی‌شود و فقط نامش را در SNI می‌گذارد.

```bash
# درست — هندشیک را می‌سنجد
openssl s_client -connect swdist.apple.com:443 -servername swdist.apple.com \
  -tls1_3 -alpn h2 </dev/null 2>&1 | grep -E "ALPN|Verify"

# گمراه‌کننده — پاسخ ۴۰۳ تحریم را با فیلتر اشتباه می‌گیرد
curl -I https://swdist.apple.com
```

اسکریپت از `openssl` استفاده می‌کند، پس درست عمل می‌کند. فقط بررسی ریدایرکت داخلش با `curl` است که ممکن است هشدار بی‌مورد بدهد.

## استفاده از نتیجه در کانفیگ Xray

بعد از پیدا کردن دامنه مناسب، سمت سرور:

```json
"streamSettings": {
  "network": "tcp",
  "security": "reality",
  "realitySettings": {
    "dest": "www.hetzner.com:443",
    "serverNames": ["www.hetzner.com"],
    "privateKey": "YOUR_PRIVATE_KEY",
    "shortIds": [""]
  }
}
```

و سمت کلاینت:

```json
"realitySettings": {
  "serverName": "www.hetzner.com",
  "fingerprint": "chrome",
  "publicKey": "YOUR_PUBLIC_KEY",
  "shortId": "",
  "spiderX": "/"
}
```

کلیدها را با `xray x25519` بسازید.

**نکته:** `dest` فقط یکی است ولی `serverNames` آرایه است. اگر SNI هایی بگذارید که با `dest` هم‌خانواده نیستند، گواهی برگشتی با SNI نمی‌خواند و در برابر پروب فعال ضعیف می‌شوید. اگر چند SNI می‌خواهید، بهتر است برای هرکدام یک اینباند جدا با `dest` هماهنگ خودش بسازید.

## فایل لیست کاندیدها

فایل `sni-candidates-big.txt` حدود ۱۵۰ دامنه دارد، دسته‌بندی‌شده بر اساس نوع شبکه:

- شبکه‌های اختصاصی اپل، گوگل، مایکروسافت و Valve
- سرورهای دانلود بازی و درایور
- مخازن توزیع‌های لینوکس
- ارائه‌دهنده‌های هاست و ابر اروپایی
- دامنه‌های صنعتی و دانشگاهی

تمرکز روی دامنه‌هایی است که ماهیت سیاسی یا اجتماعی ندارند و کمتر هدف فیلترینگ محتوایی قرار می‌گیرند.

آزادانه کم و زیادش کنید. فرمت ساده است: هر خط یک دامنه، `#` برای کامنت.

## محدودیت‌ها

- وضعیت فیلترینگ روزانه تغییر می‌کند و بین اپراتورهای مختلف فرق دارد. نتیجه امروز تضمین فردا نیست
- کد کشور از منبع Cymru مبنای ثبت تخصیص است نه موقعیت فیزیکی
- اسکریپت فقط IPv4 را بررسی می‌کند
- بررسی ریدایرکت روی دامنه‌هایی که آی‌پی شما را تحریم کرده‌اند ممکن است هشدار بی‌مورد بدهد

به همین دلیل توصیه می‌شود چند دامنه سالم را به‌عنوان استخر پشتیبان نگه دارید و اگر یکی از کار افتاد سریع جایگزین کنید.
